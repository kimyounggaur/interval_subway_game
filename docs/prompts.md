# 음정 지하철 — 프롬프트 설계서

버전 1.0 · 작성 2026-11-12 · 기획서 1.1 기준

「음정 지하철」을 AI 코딩 도구와 대화하며 만드는 순서와 프롬프트입니다. 단계는 16개이고 선택 단계가 1개 있습니다.

## 사용법

- 프롬프트는 회색 상자 안을 통째로 복사해 AI 코딩 도구(Claude Code 등)에 붙여 넣습니다.
- '확인 방법'을 통과한 뒤에 다음 단계로 갑니다. 통과하지 못하면 '막혔을 때'의 프롬프트를 씁니다.
- 대화가 길어져 새 대화를 열었다면 맨 아래 '자주 쓰는 프롬프트'의 **이어가기**를 먼저 붙여 넣습니다.
- 규칙과 수치는 이 문서가 아니라 기획서가 기준입니다. 프롬프트에는 기획서의 장 번호만 적었습니다.

## 준비

1. 컴퓨터에 Node.js(LTS 버전), Git, AI 코딩 도구가 설치되어 있어야 합니다. 배포에는 GitHub 계정과 Vercel 계정이 필요합니다.
2. 작업할 폴더를 만듭니다. 이름은 `interval-subway`로 합니다.
3. 그 안에 `docs` 폴더를 만들고 받은 파일을 넣습니다. 그림 5장은 `docs` 안에 `mock` 폴더를 만들어 넣습니다. 묶음 파일 `interval-subway-docs.zip`을 받았다면 압축을 풀어 나온 `docs` 폴더를 그대로 넣으면 됩니다. 묶음 파일 안에서는 기획서가 `spec.md`, 이 문서가 `prompts.md`라는 이름으로 들어 있습니다(단계 1에서 바꾸는 이름과 같습니다).

| 받은 파일 | 내용 | 넣는 곳 |
|---|---|---|
| `음정지하철_기획서.md` | 무엇을 만드는지의 기준 | `docs/` |
| `음정지하철_프롬프트설계서.md` | 이 문서 | `docs/` |
| `interval.reference.ts` | 참조 엔진. 음정 계산, 문제 뽑기, 채점, 스탬프, 안내 문장 | `docs/` |
| `interval_golden_v1.json` | 검증 자료. 엔진의 정답 | `docs/` |
| `interval_golden_test.ts` | 검증 시험. 엔진을 검증 자료와 대조한다 | `docs/` |
| `music-glyphs.json` | 악보 기호(음자리표, 음표, 임시표)의 윤곽선 | `docs/` |
| `mock-1-line.png` ~ `mock-5-free-ride.png` | 플레이 화면 시안 그림 5장 | `docs/mock/` |

4. AI 코딩 도구를 `interval-subway` 폴더에서 엽니다.

## 단계 1. 작업 규칙 세우기와 파일 정리

목표: AI가 기획서를 기준으로 삼고, 한 단계씩만 진행하고, 검증 자료를 건드리지 않게 약속을 정합니다.

```
이 폴더에서 「음정 지하철」이라는 모바일 웹 게임을 만들 거야. 음정 이론(도수와 성질)을 지하철 노선과 역으로 배우는 학습 게임이야. 나는 개발자가 아니고, 너와 대화하면서 한 단계씩 만든다.

먼저 다음을 해 줘.
1. docs 폴더의 파일 이름을 확인하고 한글 이름은 바꿔 줘. 한글 파일명은 맥과 윈도우 사이에서 깨질 수 있어서야.
   - 음정지하철_기획서.md → docs/spec.md
   - 음정지하철_프롬프트설계서.md → docs/prompts.md
   - 이미 spec.md, prompts.md 로 되어 있으면 그대로 둔다.
   - interval.reference.ts, interval_golden_v1.json, interval_golden_test.ts, music-glyphs.json, mock 폴더의 그림 5장은 이름을 바꾸지 않는다.
2. docs/spec.md 를 처음부터 끝까지 읽어 줘. docs/mock 의 그림 5장도 봐 줘. docs/interval_golden_v1.json 은 약 320KB라서 열어 읽지 마. 구조는 spec.md 부록 F에 있다.
3. 네가 매번 읽는 프로젝트 지침 파일(Claude Code면 CLAUDE.md, 다른 도구면 AGENTS.md)에 아래 [작업 규칙]을 그대로 넣어 줘. 파일이 이미 있으면 지우지 말고 덧붙여 줘.
4. git 저장소를 만들고 첫 커밋을 해 줘.
5. 끝나면 spec.md 의 내용을 다섯 줄로 요약하고, 모순돼 보이거나 이해가 안 되는 부분이 있으면 알려 줘. 아직 코드는 만들지 마.

[작업 규칙]
- 기준 문서는 docs/spec.md 다. 구현이 문서와 다르면 문서가 맞다. 문서에 없는 규칙을 만들거나 바꾸지 않는다. 문서가 모호하거나 틀려 보이면 멈추고 나에게 묻는다.
- 한 번에 한 단계만 한다. 단계는 docs/prompts.md 의 순서를 따른다. 내가 다음 단계를 시키기 전에는 넘어가지 않는다.
- 규칙의 정답은 docs/interval.reference.ts 와 docs/interval_golden_v1.json 이다. 시험이 실패하면 프로젝트의 코드를 고친다. 검증 자료, 검증 시험의 기대값과 비교 방법, spec.md 의 기준 수치는 고치지 않는다.
- docs/interval_golden_v1.json 은 통째로 읽지 않는다. 시험 코드에서 불러 쓴다.
- src/game 폴더의 코드는 화면이나 브라우저 기능을 쓰지 않는다. 화면과 저장 쪽에서는 음정, 정답, 스탬프, 안내 문장을 다시 계산하거나 새로 만들지 않고 엔진이 돌려준 값만 쓴다.
- 악보의 음자리표, 음표, 임시표는 docs/music-glyphs.json 의 윤곽선으로 그린다. 일반 글꼴의 ♭, ♯ 글자를 쓰지 않는다.
- 화면 모양은 docs/mock 의 그림과 spec.md 7장을 따른다. 그림과 문서가 다르면 문서가 맞다(spec.md 3.4).
- 새 라이브러리가 필요하면 이유를 말하고 내 허락을 받은 뒤 설치한다.
- 단계를 마치면 시험, 형식 검사, 타입 검사를 돌려 통과시킨 뒤 "단계 N 완료: 요약"이라는 메시지로 커밋한다.
- 보고는 쉬운 한국어로 한다. 단계가 끝날 때마다 ① 무엇을 만들었는지 ② 내가 직접 확인하는 방법(주소, 누를 단추, 보여야 할 화면) ③ 확인하지 못했거나 남은 문제를 구분해서 알려 준다. 긴 로그는 붙이지 않는다.
- 화면 문구는 한국어로, 짧은 존댓말로 쓴다(spec.md 8.1).
```

확인 방법
- `docs` 폴더에 `spec.md`, `prompts.md`, `interval.reference.ts`, `interval_golden_v1.json`, `interval_golden_test.ts`, `music-glyphs.json`과 `mock` 폴더(그림 5장)가 있습니다.
- AI의 요약에 "노선은 도수, 역은 성질", "구간 5개와 스탬프", "참조 엔진과 검증 자료"가 들어 있습니다.
- AI가 모순이나 질문을 내놓으면 다음 단계로 가기 전에 답합니다. 답하기 어려우면 이 설계서를 만든 대화로 가져와 물어보세요.

## 단계 2. 프로젝트 뼈대

목표: 빈 화면이라도 브라우저에 뜨는 프로젝트를 만듭니다.

```
docs/prompts.md 의 단계 2를 진행하자. docs/spec.md 1장, 7.1, 7.2, 12장을 읽고 프로젝트 뼈대를 만들어 줘.

- Next.js(App Router) + TypeScript(strict) + Tailwind CSS + Zustand + Vitest. 버전은 지금 안정 버전으로. Next.js 는 버전마다 쓰는 법이 달라졌을 수 있으니, 프로젝트 안에 Next.js 의 문서(node_modules/next/dist/docs)가 있으면 그것을 먼저 읽어 줘.
- 지금 폴더에 만든다. docs 폴더와 그 안의 파일은 그대로 남아야 한다. 프로젝트 생성 도구가 "폴더가 비어 있지 않다"고 하면 임시 폴더에 만든 뒤 옮겨 줘.
- 프로젝트 생성 도구가 AGENTS.md 나 CLAUDE.md 를 새로 만들면 단계 1에서 넣은 [작업 규칙]과 합쳐 줘. [작업 규칙]이 지워지면 안 된다.
- 서버 기능 없이 정적 파일만으로 동작하게 설정한다(정적 내보내기). 프로젝트 생성 도구가 넣은 기본 설정 가운데 정적 내보내기와 함께 쓸 수 없는 것이 있으면 끈다. 빌드가 그 설정 때문에 실패하면 오류 문구가 알려 준다.
- docs 폴더는 타입 검사, 형식 검사, 시험, 빌드의 대상에서 뺀다. docs 안의 .ts 파일은 참고용 원본이라서 그 자리에서는 동작하지 않는다.
- Vitest 를 설치할 때 @types/node 버전이 맞지 않는다는 오류가 나면 @types/node 를 지금 쓰는 Node.js 버전에 맞게 올린다.
- spec.md 12장의 폴더 구조를 만든다. 아직 내용은 비워 둔다.
- 글꼴은 Noto Sans KR(굵기 500, 700, 900)이다. 바탕색, 글자색, 노선 색은 spec.md 7.2의 값을 한 곳에 정의해 두고 쓴다.
- 폰 세로 화면이 기준이다. 넓은 화면에서는 가운데에 최대 폭 480px 기둥으로 보이게 한다.
- 홈 화면에는 제목 "음정 지하철"과 "준비 중이에요" 문구만 둔다.
- 명령을 준비한다: 개발 서버, 빌드, 시험, 형식 검사, 타입 검사.
- 개발 서버를 띄우고, 내가 브라우저에서 열 주소를 알려 줘.
```

확인 방법
- AI가 알려 준 주소(보통 `http://localhost:3000`)를 브라우저에서 열면 크림색 바탕에 남색 글자로 "음정 지하철" 제목이 보입니다.
- AI의 보고에 빌드, 시험, 형식 검사, 타입 검사가 모두 통과했다고 적혀 있습니다.
- `docs` 폴더의 파일 6개와 `mock` 폴더가 그대로 있습니다.

막혔을 때

```
개발 서버 주소를 열었는데 화면이 안 떠. 터미널에 나온 오류를 읽고 원인을 한 문장으로 설명한 다음 고쳐 줘. 고친 뒤 다시 주소를 알려 줘.
```

## 단계 3. 엔진 들여오기와 검증

목표: 참조 엔진을 프로젝트에 넣고, 검증 자료로 전부 맞는지 확인합니다. 이 단계가 통과하면 음정 계산, 문제 뽑기, 채점, 스탬프, 안내 문장이 맞게 들어간 것입니다.

```
docs/prompts.md 의 단계 3을 진행하자. docs/spec.md 5장, 6.2~6.6, 부록 F, 부록 G를 읽어 줘.

1. docs/interval.reference.ts 를 src/game/ 으로 들여온다. 이 파일은 음정 계산, 문제 뽑기, 채점, 스탬프, 안내 문장을 모두 가진 참조 구현이고 검증 자료를 전부 통과한다.
   - 그대로 써도 되고 파일을 나눠도 된다(예: 계산, 설정값, 판 만들기, 채점). 설정값은 src/game/config.ts 에 둔다.
   - 함수의 이름과 뜻, 난수를 쓰는 순서는 바꾸지 않는다. 고치거나 "개선"하지 않는다.
   - src/game/index.ts 에서 spec.md 부록 G의 이름을 모두 다시 내보낸다.
2. docs/interval_golden_test.ts 를 src/game/__tests__/golden.test.ts 로 복사한다. 맨 위의 엔진 import 한 줄만 프로젝트에 맞게 고치고, 나머지(기대값, 비교 방법)는 고치지 않는다. docs 에 있는 원본 파일들은 그대로 둔다.
3. 시험을 돌린다. golden.test.ts 의 시험 57개가 모두 통과해야 한다.
4. 모의 실행 명령을 만든다(scripts/sim.ts, npm run sim). 엔진의 simulatePace 로 spec.md 부록 F.5의 18줄을 2,000번씩 돌려 표로 출력하고, docs/interval_golden_v1.json 의 partB.pace 와 한 줄씩 비교해 마지막 줄에 "18줄 모두 같음" 또는 다른 줄의 목록을 쓴다. 스크립트를 실행하는 데 tsx 같은 도구가 필요하면 설치해도 된다.
5. 끝나면 시험이 몇 개 통과했는지와 모의 실행의 마지막 줄을 알려 줘.

검증 자료 파일은 통째로 읽지 말고 시험 코드에서만 불러 써. 시험이 실패하면 검증 자료나 시험의 기대값이 아니라 들여온 엔진 쪽을 고쳐. 들여오면서 규칙이 달라졌다는 뜻이야.
```

확인 방법
- AI의 보고에 "검증 시험 57개 통과, 실패 0"이 있습니다. 57개에는 판 재생 기록 18개와 안내 문장 예문 20개가 들어 있습니다.
- 모의 실행의 마지막 줄이 "18줄 모두 같음"입니다. 구간 ②의 확률 100% 줄은 열림 3.00, 완주 3.86입니다.
- 숫자가 다르면 일부만 확인했거나 엔진이 달라진 것입니다. 아래 프롬프트를 씁니다.

## 단계 10. 문제 화면 2: 역 만들기, 한 칸 이동
